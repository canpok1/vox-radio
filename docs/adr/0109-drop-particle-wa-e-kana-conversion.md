# 0109. 助詞の wa/e 化（は→わ、へ→え）を廃止する（ADR-0094 改訂）

- ステータス: 採用
- 日付: 2026-08-28

## コンテキスト

ADR-0094 は、助詞の「は」「へ」を発音どおり「わ」「え」にひらがなで書き換えるルール（wa/e 化）を direct.md・proofread.md に導入した。目的は「語頭のひらがな は/へ が助詞と誤解析され自立語が誤読される」ケースの回避で、かな化した漢字の読みをカタカナで書く（自立語=カタカナ／助詞=ひらがな、の対立で解析を助ける）というルールの一部だった。

このカタカナ化は ADR-0103 で廃止され、漢字は常に元表記のまま VOICEVOX(OpenJTalk) の読み推定に委ねる方式になった。wa/e 化は「ADR-0103 と独立した OpenJTalk 対策」として明記のうえ維持されたが、実際に検証すると前提が崩れていた。

- **前提が再現しない。** pyopenjtalk で8例試したが、wa/e 化しなくても助詞の誤読は1件も再現しなかった（例: 「はれのちくもり」→「ハレノチクモリ」、「へやにはいる」→「ヘヤニハイル」）。
- **効果が無い。** 書き換えの有無で読みが変わらない（例: 「私は行く」「私わ行く」はどちらも「ワタシワイク」）。
- **単独の根拠が記録に無い。** `git log -S` で prompts の履歴を追うと、助詞の wa/e 化の初出は ADR-0094 の実装コミット自身であり、それ以前に既存ルールは無い。「維持する」という体裁だが実質は新設で、ルール自体の根拠が別途示されたことはない。
- **LLM の言語常識と衝突し続ける。** proofread の corrections を4話分（ep111・112・115・118）分類すると、正しい向き（は→わ）の修正は一度も観測されず、全て逆向き（わ→は、LLM が書き換えを巻き戻す方向）だった。プロンプトで指示しても実運用で守られていない。

実測は pyopenjtalk（VOICEVOX 同梱辞書とは版が異なりうる）で行っており、決定的な確認にはエンジン実機が要る。ただし「書き換えても読みが変わらない」ことが崩れても、廃止して困るのは「書き換えないと誤読される」場合のみで、それは上記の再現実験で否定されている。

## 決定

助詞の wa/e 化ルールを direct.md・proofread.md から削除する。英単語・英語ファイル名の変換、誤読・意味不明の検出など、他の読み変換・校正ルールは維持する。

## 結果

- 良い影響: 効果のない書き換えとその巻き戻しが無くなり、LLM 呼び出し・修正適用の無駄が減る。proofread が「仕様どおり動いていない」状態（逆向きの修正を出し続ける）も解消する。
- 悪い影響: 将来 VOICEVOX(OpenJTalk) の実機で助詞の誤読が確認された場合、対策を再検討する必要がある（現時点では pyopenjtalk の検証結果からその可能性は低いと判断）。

## 検討した代替案

- proofread のプロンプトを修正し、wa/e 化の向きを守らせる案: LLM の言語常識（「は」を「わ」と書くのは表記として不自然）と衝突し続けており、プロンプトの言い回しを変えても同じ揺り戻しが起きる可能性が高いため却下。
