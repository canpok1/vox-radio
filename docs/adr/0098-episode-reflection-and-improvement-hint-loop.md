# 0098. 番組の振り返りと改善案注入による自動改善ループを導入する

- ステータス: 採用
- 日付: 2026-07-27

## コンテキスト

番組の質を改善する手段は利用者が `script_note` / `direction` を手で書き換えることだけで、何が悪かったかは生成物を人が読まないと分からず、回を重ねても知見が蓄積しない。

組み込みプロンプトは差し替えできない（ADR-0023）ため改善余地は「プロンプトへ注入される入力」に限られる。履歴キャッシュは既に過去エピソード文脈を `write` へ渡しており（ADR-0018 / ADR-0019）、回をまたぐ受け渡し口として再利用できる。

`internal/eval`（ADR-0049）は組み込みプロンプトを CI で測る開発者向け機構で、番組をランタイムで測るものではないため流用しない。

## 決定

振り返り生成・改善案生成・改善案注入の3段を分離した改善ループを導入する。

| 段 | 実行契機 | 処理 | 出力 |
|---|---|---|---|
| reflect | 番組生成の直後 | LLM の定性評価＋機械メトリクス（目標尺 `length_sec` と実測尺の乖離・校正修正件数・話者別セリフ量）で振り返りを生成 | `07_reflection.json` とキャッシュの `reflection` フィールド |
| improve | `vox-radio improve`（定期実行） | 直近 N 件の振り返りから反復課題を抽出 | `.vox-radio/improve/<program_id>.yaml`（全置換） |
| 注入 | `episodegen` 起動時 | 改善案を `write` プロンプトの `{{improvement_hints}}` へ注入 | — |

reflect は `internal/reflection` に新設し、呼び出しは合成点の `cli` 層へ置く（入力は中間ファイル経由 = ADR-0004）。`pipeline` のステップにすると全ステップ error 返却の作法上、振り返り失敗で完成済みの番組を捨てることになるため避けた。個別実行用に `episodegen reflect` も設ける。improve は別ライフサイクルのためトップレベルサブコマンドとする（ADR-0028）。

改善案は個別承認を要さず自動適用し、暴走と方針ドリフトは次の安全弁で抑える。

| 安全弁 | 内容 |
|---|---|
| 人の指示を上位に置く | `script_note` と矛盾する改善案は前者を採ることを `write.md` に明記。番組の基本コンセプトは変更しない |
| 件数上限 | `improve.max_hints`（既定 5） |
| 停止スイッチ | `improve.apply`（既定 true）。false でも振り返りの蓄積は続く |
| 参照範囲の限定 | `improve.reflection_entries`（既定 5）。古い課題を引きずらない |

機械メトリクスの併走は、書いたモデルが自作を採点する自己評価バイアスの緩和として必須とする。

## 結果

回を重ねるほど番組が改善される。振り返りは単体でも弱点を読める成果物であり、improve を待たずに価値が出る。

受け入れる制約:

- **自己評価バイアスは残る**。改善案が一般論に収束したら `apply` を false にし人の `script_note` へ寄せる。
- **手編集は永続しない**。improve は全置換のため消した項目は復活しうる。恒久的な方針は `script_note` に書く使い分けを明記する。
- `.vox-radio/` は gitignore 対象で世代差分を追えない。`generated_at` と `source_episodes` に留め、履歴ファイルは作らない。
- 単発番組（`single_shot`）はキャッシュに保存しないため（ADR-0086）improve の対象外。振り返りは中間ファイルへ出す。
- LLM 呼び出しが番組生成ごとに1回増える。

## 検討した代替案

- **個別承認制にする**: ドリフトを防げるが毎回の承認作業が目的を損なう。停止スイッチと件数上限で代替する。
- **`episode-spec.yaml` へ書き戻す**: git 差分で追えるが、人が管理する設定を機械が書き換えると書式破壊・衝突を招くため不採用。
- **振り返りを独立 JSONL に置く**: `cache` の責務は膨らまないが、回番号の紐付けと保持期間管理の再実装が必要なため不採用。
- **人手フィードバックを起点にする**: 精度は高いが毎回書く運用コストが目的に反するため見送る。
- **`direct` / `rundown` にも注入する**: 範囲は広がるが変数が増えて因果が追えず、記事選定への介入は再現性も下げるため見送る。
