# 0098. 回ごとの分析と振り返りによる自動改善ループを導入する

- ステータス: 採用
- 日付: 2026-07-27

## コンテキスト

番組の質を改善する手段は利用者が `script_note` / `direction` を手で書き換えることだけで、何が悪かったかは生成物を人が読まないと分からず、回を重ねても知見が蓄積しない。

組み込みプロンプトは差し替えできない（ADR-0023）ため改善余地は「プロンプトへ注入される入力」に限られる。履歴キャッシュは既に過去エピソード文脈を `write` へ渡しており（ADR-0018 / ADR-0019）、回をまたぐ受け渡し口として再利用できる。

`internal/eval`（ADR-0049）は組み込みプロンプトを CI で測る開発者向け機構で、番組をランタイムで測るものではないため流用しない。

## 決定

回ごとの分析・振り返り・改善案注入の3段を分離した改善ループを導入する。

| 段 | 実行契機 | 処理 | 出力 |
|---|---|---|---|
| analyze | 番組生成の直後 | 実セリフから課題（findings）と会話の型（patterns）を抽出し、機械メトリクス（目標尺 `length_sec` と実測尺の乖離・校正修正件数・話者別セリフ量）と合成 | `07_analysis.json` とキャッシュの `analysis` フィールド |
| retro | `vox-radio retro`（定期実行） | 直近 N 件の分析から反復する課題と型を抽出し、1本の自由記述にまとめる | `.vox-radio/retro/<program_id>.yaml`（番組ごと1ファイル・全置換） |
| 注入 | `episodegen` 起動時 | 改善案を `write` プロンプトの `{{retro_note}}` へ注入 | — |

工程名は1回分を調べる `analyze` と複数回を振り返る `retro`（レトロスペクティブの語義）に対応させた。

analyze は `internal/analyze` に新設し、呼び出しは `cli` 層に置く（入力は中間ファイル経由 = ADR-0004）。`pipeline` のステップにすると error 返却の作法上、分析失敗で完成済みの番組を捨てるため避けた。個別実行用に `episodegen analyze` も設ける。retro はトップレベルとする（ADR-0028）。

改善案は個別承認を要さず自動適用し、ドリフトは次の安全弁で抑える。

| 安全弁 | 内容 |
|---|---|
| 人の指示を上位に置く | `script_note` と矛盾する改善案は前者を採ることを `write.md` に明記。番組の基本コンセプトは変更しない |
| 分量上限 | `retro.note_length`（既定 400 文字程度）。件数ではなく分量で縛るのは、制約したいのが write プロンプトを占める割合であり、1件あたりの長さがばらつく件数指定では制御できないため。人が書く `script_note` と同じ自由記述形式に揃える。上限はプロンプトで指示するだけで Go 側では切らない（`summary_length` と同じ扱い） |
| 停止手段 | 生成を止めるなら retro を実行しない。適用を止めるなら改善案ファイルを削除する（専用の設定フラグは置かない） |
| 参照範囲の限定 | `retro.analysis_entries`（既定 5）。古い課題を引きずらない |
| 引き継ぎに根拠を要求 | retro は前回の改善案を参照するが、引き継ぐのは直近の分析にまだ根拠がある項目のみ。解消済みは落とす。根拠がウィンドウから抜けた指示がコピーされ続けて居座るのを防ぐ |

機械メトリクスの併走は自己評価バイアスの緩和に必須とする。

会話の型を analyze 時点で記録するのは、型の固定化が1回分の課題や要約からは見えず、複数回の実セリフを並べないと検出できないため。retro は中間ファイルを参照せずキャッシュ集約された型を比較する（ADR-0018 / 0019 踏襲）。

## 結果

回を重ねるほど番組が改善される。回ごとの分析は単体でも弱点を読める成果物で、retro を待たずに価値が出る。

受け入れる制約:

| 制約 | 内容 |
|---|---|
| 自己評価バイアスは残る | 改善案が一般論に収束したら改善案ファイルを削除し人の `script_note` へ寄せる |
| retro を止めても適用は続く | 既存の改善案ファイルは `episodegen` のたびに注入される。適用を止めるにはファイル削除が必要（README に明記する） |
| 手編集は永続しない | retro は全置換のため消した項目は復活しうる。恒久的な方針は `script_note` に書く運用を明記する |
| 世代差分は追えない | `.vox-radio/` は gitignore 対象。`generated_at` と `source_episodes` に留め履歴ファイルは作らない |
| 単発番組は対象外 | `single_shot` はキャッシュに保存しないため（ADR-0086）retro の入力にならない |
| 型は analyze 時点の観点に固定される | 抽出観点を変えても過去回は取り直せない（中間ファイルが残る回のみ `episodegen analyze` で再生成可） |
| LLM 呼び出しが1回増える | 番組生成ごと |

## 検討した代替案

- **個別承認制にする**: ドリフトを防げるが毎回の承認作業が目的を損なう。分量上限と削除で代替。
- **`episode-spec.yaml` へ書き戻す**: git 差分で追えるが、機械が人の設定を書き換えると書式破壊・衝突を招くため不採用。
- **分析を独立 JSONL に置く**: 回番号の紐付けと保持期間管理を再実装するため不採用。
- **retro が過去回の中間ファイルを横断参照する**: 実セリフを直接比較できるが、`--force` で消え out-dir も利用者管理のため環境で結果が変わる。全台本 N 回分のトークン量も重い。
- **適用停止を設定フラグで持つ**: 生成物を壊さず切れるが、生成停止は retro を実行しないこと、適用停止はファイル削除で足りるため不採用。
- **N 件のリストで持ち件数で縛る**: 型の反復検出は analyze の `patterns` 側で行うため構造は不要で、件数では分量を制御できないため自由記述へ変更した。
- **人手フィードバックを起点にする**: 精度は高いが毎回書く運用コストが目的に反するため見送る。
- **`direct` / `rundown` にも注入する**: 範囲は広がるが変数が増えて因果が追えず、記事選定への介入は再現性も下げるため見送る。
