# 0098. 回ごとの分析と振り返りによる自動改善ループを導入する

- ステータス: 採用
- 日付: 2026-07-27

## コンテキスト

番組の質を改善する手段は利用者が `script_note` / `direction` を手で書き換えることだけで、何が悪かったかは生成物を人が読まないと分からず、回を重ねても知見が蓄積しない。

組み込みプロンプトは差し替えできない（ADR-0023）ため改善余地は「プロンプトへ注入される入力」に限られる。履歴キャッシュは既に過去エピソード文脈を `write` へ渡しており（ADR-0018 / ADR-0019）、回をまたぐ受け渡し口として再利用できる。

`internal/eval`（ADR-0049）は組み込みプロンプトを CI で測る開発者向け機構で、番組をランタイムで測るものではないため流用しない。

## 決定

分析・振り返り・注入の3段を分離した改善ループを導入する。

| 段 | 実行契機 | 処理 | 出力 |
|---|---|---|---|
| analyze | 番組生成の直後 | 実セリフから課題（findings）と会話の型（patterns）を抽出し、機械メトリクス（目標尺 `length_sec` と実測尺の乖離・校正修正件数・話者別セリフ量）と合成 | `07_analysis.json` とキャッシュの `analysis` フィールド |
| retro | `vox-radio retro`（定期実行） | 直近 N 件の分析から問題と施策を組にして記録し、効果が確認された施策を実証済みへ昇格 | `programs/{program_id}/try.yaml`（試行中）/ `programs/{program_id}/keep.yaml`（実証済み、ADR-0099） |
| 注入 | `episodegen` 起動時 | `write` プロンプトの `{{retro_keep}}`（守る）と `{{retro_try}}`（今回試す）へ注入 | — |

工程名は1回分の `analyze` と複数回の `retro`（レトロスペクティブの語義）に対応させた。

analyze は `internal/analyze` に新設し、呼び出しは `cli` 層に置く（入力は中間ファイル経由 = ADR-0004）。`pipeline` のステップにすると error 返却の作法上、分析失敗で完成済みの番組を捨てるため避けた。個別実行用の `episodegen analyze` も設ける。retro はトップレベル（ADR-0028）。

**試行中と実証済みを分ける**のは、施策が効いて問題が消えたときに施策も消すと再発するため（発振）。問題の未発生を「効いた証拠」として扱い実証済みへ昇格させ、注入を続けることで防ぐ。KPT の Keep / Problem / Try に対応する。

改善案は個別承認を要さず自動適用し、ドリフトは次の安全弁で抑える。

| 安全弁 | 内容 |
|---|---|
| 人の指示を上位に置く | `script_note` と矛盾する施策は前者を採ることを `write.md` に明記。番組の基本コンセプトは変更しない |
| 同時試行数の上限 | `retro.max_tries`（既定 3）。同時に多数の施策を試すとどれが効いたか切り分けられない。分量ではなく件数で縛るのは、制約したいのが実験の並行数だから |
| 昇格に連続実績を要求 | 問題が `retro.keep_threshold`（既定 3）回連続で発生しなければ実証済みとする。同じ回を二度数えないため try に `last_evaluated_episode` を持たせ、それより新しい回だけ数える |
| keep は retro が書き換えない | 実証済み方針の安定性を守るため、統合や一般化をしない。`retro.keep_length`（既定 600 文字）超過時は警告のみ出し `script_note` への移行を促す |
| 停止手段 | 生成を止めるなら retro を実行しない。適用を止めるなら try / keep ファイルを削除する（専用の設定フラグは置かない） |
| 参照範囲の限定 | `retro.analysis_entries`（既定 5）。古い課題を引きずらない |

機械メトリクスの併走は自己評価バイアスの緩和に必須とする。

会話の型を analyze 時点で記録するのは、型の固定化が1回分の課題や要約からは見えず複数回の実セリフを並べないと検出できないため。retro はキャッシュ集約された型を比較する（ADR-0018 / 0019 踏襲）。

## 結果

回を重ねるほど番組が改善される。効いた施策は keep に残るため問題が解消しても再発しない。回ごとの分析は単体でも弱点を読める成果物で、retro を待たずに価値が出る。

受け入れる制約:

| 制約 | 内容 |
|---|---|
| 自己評価バイアスは残る | 施策が一般論に収束したら try / keep を削除し人の `script_note` へ寄せる |
| 手編集は永続しない | retro は try / keep を全置換する。恒久的な方針は `script_note` に書く運用を明記する |
| keep は人が整理する前提 | 放置すると増え続ける。`keep_length` 超過の警告を見て `script_note` へ移す |
| 効果判定は問題の未発生に依存 | 施策と無関係に問題が消えた場合も実証済みと判定しうる |
| 世代差分は追えない | `.vox-radio/` は gitignore 対象。`generated_at` と発生回に留め履歴ファイルは作らない |
| 単発番組は対象外 | `single_shot` はキャッシュに保存しないため（ADR-0086）retro の入力にならない |
| LLM 呼び出しが1回増える | 番組生成ごと |

## 検討した代替案

- **1本の自由記述で持つ**: 分量を直接縛れるが、効いた施策と試行中を区別できず問題が解消すると再発する（初版。発振のため改訂）。
- **retro が keep を統合・一般化する**: 人手なしで分量を保てるが、実証済み方針を LLM が書き換え keep の安定性を損なう。
- **個別承認制にする**: ドリフトを防げるが毎回の承認作業が目的を損なう。安全弁で代替。
- **`episode-spec.yaml` へ書き戻す**: git 差分で追えるが、機械が人の設定を書き換えると書式破壊・衝突を招く。
- **分析を独立 JSONL に置く**: 回番号の紐付けと保持期間管理を再実装するため不採用。
- **retro が中間ファイルを横断参照する**: 実セリフを直接比較できるが、`--force` で消え out-dir も利用者管理のため環境で結果が変わる。
- **適用停止を設定フラグで持つ**: 生成停止は retro 未実行、適用停止はファイル削除で足りるため不採用。
