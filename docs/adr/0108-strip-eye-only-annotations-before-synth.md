# 0108. 合成テキストから読み上げ対象外の注釈（丸括弧の中身）をコードで除去する

- ステータス: 採用
- 日付: 2026-08-25

## コンテキスト

生成した番組で同じ単語が二度発音される現象が報告された。実際の中間生成物（vox-radio-broadcast の GitHub Actions アーティファクト ep106〜115 の 10 話）を突き合わせたところ、台本原文（`03_lines.json`）には丸括弧が 1 件も無いのに、読み変換後（`04_script.json`）に「エーダブリューエス（AWS）」「キータ（Qiita）」「エバル（イーバル）」のような**読みと原綴りの併記**が現れていた。10 話中 2 話・計 8 行で発生し、1 行に 5 件併記された例もある。

セリフのテキストは `/audio_query` へプレーン文字列としてそのまま渡る（ADR-0103）。VOICEVOX が使う OpenJTalk は括弧の中身も読み上げるため、併記はそのまま二重発音になる。pyopenjtalk による実測:

| 入力 | 読み |
| --- | --- |
| `エーダブリューエス（AWS）を使えば` | エーダブリューエス（エーダブリューエス）ヲツカエバ |
| `キータ（Qiita）の人気記事` | キータ（キューアイアイティーエー）ノニンキキジ |
| `エバル（イーバル）の設計` | エバル（イーバル）ノセッケー |

原因は、**セリフのテキストには「読ませない注釈」を書く場所が無いのに、その前提がどこにも明示されていなかった**ことにある。`direct.md` は「英単語を発音を表す日本語に置き換える」としか指示しておらず、LLM は画面向けの親切な書式である「読み（原綴り）」を選ぶ余地があった。同じ軸で、ルビ形式の併記・`（笑）` のようなト書き・記号による補足も、書けば必ず音になる。

## 決定

**synth へ渡すテキストは読み上げてほしい音だけを含む**という不変条件を、プロンプトとコードの二層で守る。

1. `direct.md` の読み変換ルールに「書いた文字はすべて読み上げられる。読ませない注釈は書けない」を追加し、原綴り・ルビの併記を禁止する。`.claude/rules/config-prompt.md` の読み変換ルール規定も、個別ケースの列挙ではなくこの前提を軸として述べる形に直す。
2. `direct` の最終段（`buildScript`）で、セリフの丸括弧 `（）` `()` とその中身を機械的に除去する。除去は釣り合った組のみを対象とし、閉じない括弧が行末を飲み込むことはない。全角・半角は組ではなく種別で判定し、`キータ(Qiita）` のような幅の混在した組も落とす（テキストを書くのは LLM であり、幅の一貫性は保証されない）。読める文字が残らない行は合成できないため元のテキストを返す。鉤括弧 `「」` `『』` は記事タイトル・引用として読み上げたいので対象外とする。
3. セリフを書くプロンプト側でも同じ前提を崩さない。`write.md` が反復を自覚させる作例として使っていた `（笑）` を、話し言葉で書いた作例に差し替える。

プロンプトだけに頼らないのは、この禁止事項が実運用で破られた実績があるためである。コード側は最後の防衛線として置き、除去が発生したら before/after をログに出す。LLM の生の `line_conversions` はどこにも保存されないため、これが「防衛線が発動した」ことと「過剰に除去していないか」を確かめる唯一の記録になる。

## 結果

- 良い影響: 併記による二重発音が LLM の出力内容によらず消える。`（笑）` のようなト書きが「ワライ」と読まれる誤読も同時に消える。除去は `direct` 段で行うため、`04_script.json` が実際に読み上げられる内容と一致する（analyze の文字数メトリクスは `03_lines.json` を数えており、除去の影響を受けない）。
- 悪い影響: 丸括弧で補足情報を伝えることができなくなる。記事タイトルに含まれる括弧書き（例:「〜の設計（後編）」）も落ちるため、その情報は音声から失われる。補足を伝えたい場合はセリフの言葉として書く必要がある。
- 防げない範囲: 括弧を使わない併記（「Qiita、キータですね」のような言い直し）や、同義語の反復による冗長は検出できない。

## 検討した代替案

- **括弧記号だけを除去して中身は残す案**: 二重発音がそのまま残るため却下。
- **「読み（原綴り）」パターンだけを検出して除去する案**（括弧内がアルファベットのときのみ等）: 「エバル（イーバル）」のようなカタカナ同士の併記を取りこぼす。パターンの列挙は必ず抜けが出て、抜けるたびに条件が増えるため却下。丸括弧そのものを音声メディアに馴染まない表記として扱うほうが境界が単純になる。
- **プロンプトの禁止ルールのみで対応する案**: 同種の指示（英単語変換）が実際に取りこぼされている実績があり（ep115 で `Qiita`・`AI` が未変換のまま残存）、LLM 依存では再発を止められないため却下。
- **synth 直前（`internal/synth`）で除去する案**: `04_script.json` と実際に読み上げられる内容が食い違い、不具合調査で中間生成物を追えなくなる。読み変換の責務を持つ `direct`（ADR-0027）で行うほうが責務分離にも合う。
