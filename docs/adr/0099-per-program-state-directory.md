# 0099. 番組ごとの状態を `.vox-radio/programs/{program_id}/` へ集約する

- ステータス: 採用
- 日付: 2026-07-27

## コンテキスト

番組ごとの状態は現在キャッシュだけで、種類ごとに階層を切る配置になっている（`.vox-radio/cache/{program_id}.jsonl`）。ADR-0098 で retro の試行中・実証済みファイルが加わると、同じ番組の状態が複数箇所へ散る。番組単位で退避・削除したいときに対象を数え上げる必要があり、いくつの番組を運用しているかもディレクトリから読めない。

キャッシュのパスは利用者側にも露出している。`feedgen --cache` は必須フラグでパスを直接受け取り、GitHub Actions ガイドは `actions/cache` の `path` に `.vox-radio/cache` を指定している。

## 決定

種類ごとではなく番組ごとに階層を切る。

```
.vox-radio/
├── logs/
│   └── 20260727-150405-episodegen.log
└── programs/
    └── morning-news/
        ├── cache.jsonl
        ├── try.yaml
        └── keep.yaml
```

ログは番組を持たないコマンド（`install` / `config check` / `assets check`）も書き、`--log-dir` は root の永続フラグのため番組単位にできない。`logs/` は独立させたまま残す。

`programs/` を挟むのは `program.id` が `logs` の番組と衝突させないため。`program.id` は空文字チェックのみで文字種を検証していない。

音声の出力先（`--out-dir`）配下には置かない。

| 論点 | 内容 |
|---|---|
| 再生成できるか | `output/` は派生物で `--force` や容量整理で消える。キャッシュはエピソード状態の正データ、retro は蓄積した知見で、どちらも再生成できない |
| フラグの階層 | `--out-dir` は `episodegen` 限定。配下に置くと `feedgen` や `retro` にも出力先の指定を強いる（ADR-0098 で retro には持たせないと決めた） |
| 実験の副作用 | `--out-dir` を変えて試すと回番号が 1 に戻り、retro の蓄積も見えなくなる |
| CI | `actions/cache` が mp3 と WAV を含むディレクトリの一部を狙う指定になる |

旧パスからの自動移行は行わない。移行は `mv` 一回で済み、Actions ではどのみちガイドの更新が要るため。

## 結果

番組単位で退避・削除でき、`ls .vox-radio/programs` で運用中の番組が分かる。retro のファイル名から番組 ID の接頭辞が要らなくなる。

利用者に必要な作業:

| 対象 | 作業 |
|---|---|
| ローカルの履歴 | `.vox-radio/cache/{id}.jsonl` を `.vox-radio/programs/{id}/cache.jsonl` へ移す。移さないと回番号が 1 に戻る |
| `feedgen --cache` | 新しいパスを渡す。ファイルが無ければ失敗するので気づける |
| GitHub Actions | `actions/cache` の `path` を `.vox-radio/programs` に変える。移行期は旧パスも併記し、復元後にワークフロー内で `mv` する移行ステップを追加する。移行ステップが無いと、旧パスを併記しても復元が静かに失敗する |

## 検討した代替案

- **`.vox-radio/{program_id}/` へ直接置く**: 階層が1つ減るが、`program.id` が `logs` の番組と衝突する。
- **ログも番組ディレクトリへ入れる**: 1番組1ディレクトリで完結するが、番組を持たないコマンドのログの置き場に例外が要る。
- **`logs/` を廃しログを `.vox-radio/` 直下へ置く**: 番組ディレクトリが直下に並び数えやすいが、ログに保持期間の仕組みが無く単調増加するため番組ディレクトリが埋もれる。
- **すべて `--out-dir` 配下へ集約する**: 単一ルートになるが、上表の4点を招く。
- **旧パスからの自動移行を実装する**: 手作業が不要になるが、Actions では旧 `path` で復元したものを新パスへ移した直後に旧 `path` を保存するため履歴が失われ、結局ガイドの更新が要る。
- **旧パスへの読み取りフォールバックを残す**: 手作業が不要になるが、書き込み先は新パスのため正データが2箇所に並び、どちらが正か分からなくなる。
