# 0097. `characters.<id>.name` を任意化し空欄で匿名キャラクターを表現する

- ステータス: 採用
- 日付: 2026-07-05

## コンテキスト

`CharacterConfig.Name`（`internal/config/characters.go:6`）は台本生成（`internal/script/write/write.go` の `buildCastInfo`）でのみ使用され、`名前=%s、一人称=%s、...` という形式でキャスト情報としてプロンプト（`internal/cli/prompts/write.md` の `{{cast_info}}`）に埋め込まれる。TTS音声選択・クレジット・フィードメタデータ・ファイル名はいずれも `CharacterID` または `Credit` を鍵にしており `Name` を参照しないため、`Name` の扱いを変えても影響範囲は `buildCastInfo` に閉じる。

一方、参照ドキュメント（`internal/cli/skills/vox-radio/references/vox-radio.md:145`）は `name` を「必須」と記載しているが、実装の `validateCharacters`（characters.go:47-56）には必須チェックが無く、ドキュメントと実装が一致していなかった。

この状況で「LLM に名前情報を渡さず、番組内で名前について触れないキャラクター（匿名キャラクター）」を表現したいという要望が出た。指定方法として、(a) 新規フィールド `nameless: true` を追加する案と、(b) 既存の `name` を空欄/省略にしたときを匿名の合図とする案を比較した。

## 決定

新規フィールドは追加せず、`characters.<id>.name` を明示的に**任意**フィールドとし、未設定または空文字（trim後空）を「匿名キャラクター」の合図とする。

匿名キャラクターの場合、`buildCastInfo` はそのキャストの行で `名前=%s、` の代わりに `名前=非公開（この人物の名前は決して明かさず、他の出演者もこの人物への呼びかけ自体を行わないこと）、` を出力する。一人称・語尾・性格・スタイル等、他のフィールドはこれまでと同様にプロンプトへ渡す。

呼びかけの扱いは「役割や特徴での自然な呼びかけを許容する」ではなく「呼びかけ自体を避ける」を採用する（ユーザー確認済み）。役割での呼びかけ（例:「そこの新人さん」）も間接的にキャラクターを識別可能にしてしまい、「番組内で名前について触れない」という要望の意図に反するため。

参照ドキュメント（`vox-radio.md` の `characters` セクション表）は `name` の必須/任意欄を「必須」から「任意」に修正し、空欄時の挙動（匿名キャラクター・呼びかけ回避）を追記する。

```yaml
characters:
  guest_a:
    # name を省略 → 匿名キャラクターとして扱われる
    pronoun: わたし
    speech_suffix: ["です", "ます"]
    personality: ["物静か", "聞き役"]
    default_style: normal
    styles:
      normal: 3
```

## 結果

- 新規スキーマフィールドを追加せずに匿名キャラクターを表現できる。既存の「フィールド未設定 = 機能オフ」という本スキーマの慣習（他の任意フィールドと同様）に沿う。
- 変更は `buildCastInfo`（`internal/script/write/write.go`）と参照ドキュメント（`vox-radio.md`）に閉じ、TTS・クレジット・フィード・ファイル名などの既存経路は無改修で動作し続ける。
- トレードオフ: `name` を空にする行為が「表示名を単に決めていない未完成設定」なのか「意図的な匿名キャラクター」なのかをスキーマ上区別できない。誤って `name` を空にした場合も匿名キャラクターとして扱われる（今回はこれを許容する）。

## 検討した代替案

- **新規フィールド `nameless: true` を追加する**: 意図が明確になり `name` が同時に非空でもエラーにできる利点はあるが、`name` の未設定という既存の任意フィールドの状態がそのまま匿名の合図として使えるため、スキーマ・バリデーションを増やすコストに対して利点が小さいと判断し却下（ユーザー確認済み）。
- **匿名キャラクターへの呼びかけを役割・特徴ベースで許容する**: 名前を明かさなくても役割ベースの呼びかけはキャラクターを間接的に識別してしまい「番組内で名前について触れない」という要望を弱めるため却下（ユーザー確認済み）。
