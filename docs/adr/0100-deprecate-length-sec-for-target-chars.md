# 0100. corners[].target_chars を新設し、length_sec / chars_per_minute を段階的に非推奨化する

- ステータス: 採用
- 日付: 2026-07-29

## コンテキスト

vox-radio-broadcast の調査（2026-07-28）で、`corners[].length_sec`（目標収録時間）を `program.chars_per_minute` で目標文字数へ換算する現行方式は、ジングル・SE・ポーズ等の演出音の尺を差し引かずセリフ文字数に全量換算しており、構造的に尺超過が起きると判明した。解決にはセリフ文字数を直接指定する `corners[].target_chars` が必要で、`length_sec` / `chars_per_minute` は非推奨とする。

これは「設定フィールドを非推奨→警告→削除の段階で移行する」手法の初適用であり、他の設定変更にも再利用できる標準パターンとして確立したい。ADR-0043 は逆に即時削除を選んでおり、使い分けを明確にする必要がある。

## 決定

`corners[].target_chars` を新設し、`length_sec` / `chars_per_minute` は非推奨化するが機能は維持する（両方指定は `episodegen check` 等でエラー）。非推奨設定使用時は、`loadConfigAndSpec` 経由の各コマンド（episodegen / check / analyze / retro 等）起動時に1回だけ警告ログを出す（対象フィールド名・代替・`references/deprecated.md` への誘導を含む）。汎用形（`config.DeprecationWarning` ＋ `EpisodeSpec.Deprecations()`）で実装し、以後の非推奨設定にも使い回す。削除時期は定めず都度判断とする。

**ADR-0043 との使い分け**: `cache.enabled` は単純な boolean で常時有効化の移行コストがほぼ無かったため即時削除できた。`length_sec` は運用中の複数番組で広く使われ、秒数→文字数という換算式を要する移行になるため即時削除は番組を壊す。移行コストが軽微なら即時削除、既存設定を広く壊す・換算を要するなら段階的非推奨、を基準とする。

## 結果

既存の `episode-spec.yaml` は無修正で動き続け、警告を見てペースを合わせて移行できる。非推奨の仕組みが汎用化され、今後の設定変更にも再利用できる。一方で `length_sec` / `chars_per_minute` のコードパスを当面残す必要があり、削除時期未定のため非推奨フィールドが長期間残るリスクがある。

## 検討した代替案

- **即時削除（ADR-0043 と同方針）**: 運用中の番組の設定を一斉に壊すため却下。
- **警告なしで無期限サポート**: 非推奨に気づかず新規番組にも古い記法が使われ続けるため却下。
- **削除時期を本決定で確定**: 移行の実態が読めない時点で期限を切ると恣意的になるため見送った。
