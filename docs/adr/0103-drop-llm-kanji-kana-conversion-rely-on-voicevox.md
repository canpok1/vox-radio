# 0103. 読み変換における漢字のLLMかな化を廃止し、VOICEVOXの読み推定に一本化する（ADR-0045・0094 改訂）

- ステータス: 採用
- 日付: 2026-08-05

## コンテキスト

現状、direct.md（ADR-0027/0094）は各セリフの漢字語のうち読み間違えやすいもの（連濁・熟字訓・複合語特殊読み・音訓混在・二人称/難読語）を、LLMが能動的にカタカナへ書き換えるルールを持つ。さらにproofread.md（ADR-0045）が変換漏れ・誤変換をLLMで検出し再度書き換える2段構成になっている。変換後テキストはVOICEVOXの`/audio_query`へプレーン文字列として渡され、残った漢字の読みはVOICEVOX(OpenJTalk)の自動推定に委ねられる。

漢字の読み間違いが多発している。原因の一つはLLM自身の読み判断の誤りであり、加えてLLMがテキストを漢字/カタカナ混在に分断して書き換えることで、VOICEVOX(OpenJTalk)の自然文解析（形態素解析・アクセント句推定）が乱れ、イントネーションの棒読み感にも影響している可能性がある。

## 決定

direct.md・proofread.mdの漢字語かな化ルール（連濁・熟字訓・複合語特殊読み・音訓混在・二人称/難読語の変換指示、および「読みが明確な漢字は漢字のまま残す」という除外規定）を例外なく完全に削除する。漢字は常に元表記のままVOICEVOXへ渡し、読み推定を全面的にVOICEVOX(OpenJTalk)に委ねる。

英単語・英語ファイル名をカタカナ変換するルールは維持する（対象はアルファベット表記のみ）。助詞のわ/え表記ルール（は→わ、へ→え）は漢字かな化と独立したOpenJTalk対策のため維持する。proofread.mdは英単語変換の校正のみに縮小し、漢字関連の検出ロジックを削除する。`.claude/rules/config-prompt.md`の読み間違い対策ルール記述もこれに整合させる。

既知固有名詞の読み誤りは、ADR-0093で導入済みの`pronunciation`静的辞書（LLM入力前の文字列置換）による個別登録に一本化する。

## 結果

- 良い影響: LLMの読み判断ミスに起因する誤読が起きなくなる。VOICEVOXへ渡すテキストが漢字を保った自然な表記になり、アクセント句推定の乱れ・棒読み感の軽減が期待できる。proofreadの漢字検出ロジック分のLLM呼び出しコストも減る。
- 悪い影響: 漢字の誤読修正手段がpronunciation辞書への手動登録のみになる。ユーザーが誤読に気づいて都度登録する運用負荷が生じ、品質がVOICEVOXの読み推定精度に直接依存する。

## 検討した代替案

- 誤読率の高いパターン（連濁など）のみ例外的にLLM変換を継続する案: 「アルファベットのみに制限」という単純な境界が崩れ、結局LLMの読み判断ミスが残るケースを排除しきれず、仕様が複雑化するため却下。
- proofreadを検出のみに転用し、テキストは書き換えずpronunciation辞書への登録をユーザーに促す案: 検出結果の提示・辞書反映までの導線を新たに実装する必要がありスコープが拡大するため、今回は見送り、まずVOICEVOX任せのシンプルな運用で様子を見る。
