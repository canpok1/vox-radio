# 0104. セリフを機械的に1文単位へ分割し、抑揚パラメータの付与を write から direct へ移す

- ステータス: 採用
- 日付: 2026-08-05

## コンテキスト

`intonation` / `pitch` / `speed` は write が生成する `model.Line` 単位で指定され、synth は Line ごとに `/audio_query` を発行する。つまり Line が抑揚の最小単位である。

1つの Line が複数の話題・感情にまたがると、その間ずっと同じ抑揚で合成される。失敗談（落ち込んだ抑揚）から気を取り直して前向きな話に移る場面で、後半も落ち込んだままになる違和感が出ている。`write.md` には「感情の変わる境目で Line を分割せよ」とあるが LLM が守らず、粒度が LLM 任せである限り保証がない。

## 決定

1. **write 出力を機械的に1文ごとへ分割する。** `regenIfNeeded` の後・`BuildScriptLines` の前に分割を挟み、`03_lines.json` には分割済みのセリフを保存する。以降の direct / synth / summary は分割後の行を見る。短い文のマージは行わず、純粋に1文＝1セリフとする。

2. **`intonation` / `pitch` / `speed` の付与を write から direct へ移す。** `model.Line` から3フィールドを削除し、direct の出力に全セリフ分の `line_voices` を追加して `model.ScriptSegment` へ設定する。direct は既にコーナー全体のセリフ列を `line_index` 単位で走査しており、LLM 呼び出しは増えない。

`style` は VOICEVOX の speaker 選択に紐づくため write に残し、分割後の各文は親の `style` と `speaker_role` を継承する。

分割だけでは各文が親の抑揚を継承するだけなので、1と2は対で入れる。

## 結果

- 良い影響: 抑揚の切り替え単位が文になり、話題転換に追随できる。write=内容 / direct=演出と責務が整理される（ADR-0003）。mix は同一話者の連続クリップ間ポーズを 0 にするため、分割で会話のテンポは崩れない。
- 悪い影響: クリップ数が2〜3倍になり合成回数・時間が増える。クリップごとに前後 0.1 秒の無音（`prePhonemeLength` / `postPhonemeLength`）が入り、句点ポーズより間延びしうる（今回は対処せず実音で判断）。direct の入出力が行数に比例して増える。

## 検討した代替案

- **機械分割のみ（パラメータは親から継承）**: 実装は最小だが、器が増えても中身が同じで抑揚は変わらず目的を達成できない。
- **write が付与し direct は変更したい行だけ上書き**: 出力量は少ないが、LLM が上書きをサボると分割の効果が出ない行が残る。
- **感情付与専用の LLM パスを新設**: 責務分離は最も明快だが LLM 呼び出しが1つ増える。direct が追加コストなしで担えるため不要。
- **write のスキーマを文の配列にして LLM に文単位で出させる**: 1コールで済むが機械的保証がなく、現状の課題が再発する。
