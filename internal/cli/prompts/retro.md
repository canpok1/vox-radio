# [D] 振り返り（retro）プロンプト

以下は、あるラジオ番組の直近{{max_tries}}件までの分析（findings・patterns）と、現行の試行中の問題一覧です。
繰り返し現れる課題を見つけ、次に試す問題と施策の組を提案してください。

## 番組情報

`direction`（演出方針）・`script_note`（台本指示）は人が決めた上位方針です。矛盾する施策は提案しないでください。

```json
{{program}}
```

## 直近の分析（回番号順）

```json
{{analyses}}
```

## 現行の試行中の問題

```json
{{current_problems}}
```

## 出力形式

以下のJSON形式で回答してください。

```json
{
  "problems": [
    {
      "id": "p1",
      "problem": "掛け合いが記事の要点を並べる説明に寄りがち",
      "action": "片方が疑問を投げてもう片方が答える形に崩す",
      "first_seen_episode": 12,
      "last_seen_episode": 16
    }
  ]
}
```

## 問題選定の注意事項

- **問題は `{{analyses}}` に実際に現れているものだけを書く**。現れていない問題を創作しない
- **`{{current_problems}}` にある問題が `{{analyses}}` にまだ現れているなら、同じ `id` で継続する**。前回の施策が効いていないということなので、`action` をより具体的に書き換える（同じ文言を繰り返さない）
- `{{analyses}}` にもう現れなくなった問題は出力から除く
- 新規の問題には `id` を付けない（空にする）。`id` は継続する問題にのみ、`{{current_problems}}` と同じ値を付ける
- **findings は複数回で反復して現れたものを優先**する。単発の課題は採らない
- **patterns は回番号順に比較し、同じ aspect でほぼ同じ detail が続いていれば固定化と見なし問題として挙げる**。逆に回ごとに変化している aspect は取り上げない
- 件数は `{{max_tries}}` 件以内にする。超える場合は反復回数・severity の高いものを優先する
- 台本生成プロンプトに既にある指示（会話の型を毎回変える、等）をそのまま繰り返さない。**具体的に何をどう崩すか**を書く

## action の注意事項

- 「もっと面白く」のような一般論を禁止する。1〜2文で、具体的に何をどう変えるかを書く
- `script_note` / `direction` / 番組の description に反する施策を書かない
